# M1 說明：基礎與生長系統

M1 打通生長系統與廚房接點，用 5 種代表作物把企劃書的六種生長型態都跑過一次。之後的里程碑主要是在資料表裡加列。

## 開發方式

```
npm run generate   # 由資料表產生方塊、物品、戰利品表、語言檔與貼圖清單
npm run validate   # 檢查 JSON、資料表互相對得上、貼圖與語言鍵都存在、manifest 相依
npm test           # 用 mock 的 @minecraft/server 跑行為測試（25 項）
npm run build      # validate + test，打包成 dist/Kaleidoscope-Harvest-v0.1.0.mcaddon
```

不需要安裝任何 npm 套件，Node 22 即可。

**改內容只改 `packs/BP/scripts/data/`**，再跑 `npm run generate`。`blocks/`、`items/`、`loot_tables/`、`recipes/`、`item_catalog/`、`texts/` 與 RP 的貼圖清單都是產生出來的，手改會被覆蓋。貼圖與 icon 一律用美術畫的檔案（`packs/RP/textures/kaleidoscope_harvest/`）；還沒畫的會列在 `docs/art/MISSING_ART.md`。

## 目錄

| 路徑 | 內容 |
| --- | --- |
| `packs/BP/scripts/main.js` | 只做啟動：註冊元件、廚房握手、送出配方與手冊 |
| `scripts/data/` | 資料表（無 `@minecraft` 匯入）：作物、果樹、物品、配方、氣候、手冊、音效粒子、簡體轉換 |
| `scripts/growth/` | 生長元件：`crops.js`（一次性／地下／可重複／兩格高／藤架）、`trellis.js`、`trees.js`、`environment.js`（氣候、溫室、光照、耕地） |
| `scripts/api/` | 廚房整合：`cookery.js` 握手、`cookeryContent.js` 配方與手冊章節 |
| `scripts/utils/blocks.js` | 方塊狀態、手持物品、掉落、音效粒子 |
| `tools/` | 產生器、驗證、測試、打包 |

## 已完成

- **生長元件**：一個 `kaleidoscope_harvest:crop` 元件負責所有田間作物，型態由資料表的 `form` 決定；欄位沿用廚房 `crop_growth` 的命名（`growthChance`、`minLightLevel`、`maxGrowth`、`harvestResetAge`）。
- **代表作物**：大白菜（一次性）、蔥（可重複採收）、玉米（兩格高）、小黃瓜（藤架）、柑橘（果樹）。地下型態的邏輯已寫好並有測試，第一個地下作物在 M2（花生、地瓜、大蒜、薑）。
- **氣候偏好**：生物群系分成寒冷／溫和／溫暖／炎熱（`data/climate.js`）。同氣候 ×1、差一級 ×0.5、差兩級不生長且葉片轉灰（`off_climate` 狀態，貼圖自動產生灰色版）。
- **溫室**：作物正上方 8 格內有玻璃屋頂（中間只有空氣或植物），且四個方向 8 格內都有牆（任何實心方塊），就視為溫室，忽略氣候。
- **竹藤架**：放在耕地上，拿小黃瓜種子點它就種下；打掉作物會還竹藤架。合成：竹子 ×6＋線 ×1 → 2 個。
- **果樹**：樹苗 4 階段後長成固定形狀（3 格果木原木＋21 塊果葉）。果葉 `fruit_stage` 無果→開花→青果→熟果，點熟果採收後回到無果。樹幹砍光後果葉在下次 random tick 掉落。果葉偶爾掉樹苗（5%），是第二棵樹的來源。（之後已改成企劃書的新做法：樹形由 `tree_feature` 生成、樹葉兩階段加垂掛果實、方塊改名 `<果樹>_leaves`、`fruitwood_log`，見 [M3 說明](M3_說明.md)。）
- **骨粉**：田間作物 +2 階段；樹苗與果葉只 +1 階段；氣候不對時骨粉無效且不消耗。
- **沉浸式回饋**：不送任何聊天或動作列文字。採收、種植、骨粉都有音效，熟作物偶爾冒粒子。廚房沒回應時只寫 content log。
- **廚房接點**：`api_ping` → `api_ready` 讀 capabilities → 逐筆 `register_recipe`（砧板、炒鍋、湯鍋、蒸籠，各自檢查 capability）→ 手冊章節分段送出（`guidebook_begin/chunk/end`）。
- **6 個配方**：蔥→蔥花（砧板）、小黃瓜→拍黃瓜（砧板）、蔥花炒蛋（炒鍋）、白菜燉肉（湯鍋）、蒸玉米（蒸籠）、橘子糖水（湯鍋）。每個代表作物至少有一個下鍋用途（驗證工具會檢查）。
- **手冊「豐收」章節**：每個物品與方塊都有條目，種植說明由資料表產生，改規則時文字會跟著變。

## 與企劃書不同的地方

| 項目 | 企劃書 | M1 做法 | 原因 |
| --- | --- | --- | --- |
| 樹形 | structure 檔 | 腳本依 `data/trees.js` 的固定形狀放置 | 可測試、不需二進位檔；之後要換 structure 只改 `growTree` |
| 創造模式分組 | 沿用廚房 `crops`、`ingredients` 分組 | 料理用 `kaleidoscope_cookery:itemGroup.name.foods`，其餘用豐收自己的分組 | 樂牧只確認過 `foods` 這個廚房分組 ID，其餘待確認 |
| 茶壺、石磨、竹篩配方 | M2 起 | 尚未註冊 | 這三種 payload 欄位樂牧沒用過，要先對廚房 API 文件 |
| PBR | 比照草本 | 尚未加 | 等正式貼圖 |
| 貼圖 | 美術 | M1 時曾用程式畫的佔位圖，後來已全部移除，改用美術 | — |

## 需要進遊戲確認（mock 測不到）

1. `dimension.getBiome()` 在 @minecraft/server 2.7.0 可用；不可用時一律當溫和氣候（不會報錯）。
2. `block.getLightLevel()` 若不存在，光照條件會略過。
3. 廚房鐮刀是否認 `kaleidoscope_cookery:crop` 方塊標籤（企劃書風險表第 2 項）。
4. 廚房水田是否帶 `kaleidoscope_cookery:farmland` 標籤；種子的 `use_on` 與作物的 `placement_filter` 都用了這個標籤描述子。
5. 音效 ID（`block.sweet_berry_bush.pick`、`item.bone_meal.use`、`use.bamboo`、`block.azalea.place`）與粒子 `minecraft:wax_particle` 是否都存在；不存在只是沒聲音，不會中斷採收。
6. 生長速度：`growthChance` 先取 0.4–0.45，實際手感要在遊戲內調。
7. 耕地被踩回泥土時，作物會依 `placement_filter` 掉落。

## M1 關卡（代表作物能完整種植、採收、下鍋）

- 種植、生長、採收：自動測試涵蓋五種代表作物，另有地下型態的單元測試。
- 下鍋：配方 payload 有測試，實際送進廚房要在遊戲內確認（上方清單第 3、4 項同場一起測）。
- 野外第一份來源屬於 M2 關卡；M1 期間種子與樹苗從創造模式取得。
