## 測試方法與限制

- 由 Claude 遠端操作遊戲：用指令搭測試場地（作物展示區、樹的平台），用截圖檢查模型。
- **模擬的滑鼠右鍵傳不進遊戲**，連原版骨粉灑草地都沒反應，所以「點方塊」的互動沒辦法直接測。
    - 改用一個臨時的測試腳本（只裝在本機的遊戲資料夾，沒有放進 repo）：輸入 `/scriptevent ht:use x y z`，讓遊戲用玩家手上的東西，呼叫該方塊的 `onPlayerInteract`。
    - 這樣測得到遊戲引擎裡的實際行為（改方塊狀態、掉落物、`placeFeature`、計時），但測不到「右鍵是否真的會觸發」這一步。這一步是遊戲本身的機制，第 2 輪請人工用滑鼠點一次確認。
- `/reload` 不會重新註冊方塊的自訂元件（遊戲記錄有寫），重新載入後作物、果實的互動全部失效。所以每次更新腳本都要退出世界再進來；這不是豐收的問題。

## 找到並修好的問題

| # | 問題 | 影響 | 修正 | 之後怎麼擋 |
| --- | --- | --- | --- | --- |
| 1 | 垂掛果實和野生作物方塊用了 `minecraft:movable`，但方塊格式是 1.21.90，遊戲要求 1.21.100 以上 | **34 個方塊整個沒載入**：10 種果實和 24 種野生作物都不存在，果樹開花後腳本一直報錯 | 方塊格式改成 1.21.100 | `npm run validate` 會檢查元件需要的最低格式版本 |
| 2 | 土壤清單用了 Java 版的 `minecraft:rooted_dirt`，基岩版叫 `minecraft:dirt_with_roots` | 樹苗、藍莓、野生樹苗的放置條件少一種土，遊戲記錄有錯誤 | 改名 | validate 會擋 Java 版方塊名 |
| 3 | 熟作物的閃光粒子 `wax_particle` 需要顏色和方向參數，沒給 | 每幀都在內容記錄寫錯誤（一場測試約 20 萬行） | 送粒子時帶上 Molang 參數（暖黃色、往上飄） | 新增測試：熟作物粒子要帶參數 |
| 4 | 柑橘、柳橙、香蕉的樹冠 `random_spread_canopy` 接在一般 `trunk` 上 | **這三種樹只長出光禿禿的樹幹、沒有葉子**，野外的柳橙樹也一樣；柑橘樹苗永遠長不大 | 改用不傾斜的 `acacia_trunk`（原版杜鵑樹的搭法） | `tree_shapes.py` 和 validate 都會擋 |
| 5 | `npm run generate` 每次都會刪掉 `pack_icon.png` | 上次 PR #7 誤刪 pack 圖示就是這個原因 | 生成器不再碰 pack 圖示 | validate 會檢查兩個 pack 圖示都在 |

## 沒測到、下一輪要測

- **所有需要真的右鍵的互動**（見上方限制），特別是：用滑鼠右鍵採收、廚房器具（砧板、石磨、炒鍋、湯鍋、蒸籠、茶壺、竹篩）做豐收的料理、植物油、手冊「豐收」章節。
- 其他生物群系的野生作物與果樹（叢林、熱帶草原、沼澤、沙漠、竹林、叢林邊緣）、村莊箱子。舊區塊裡已經生成的光禿柳橙樹幹不會自己修好，要看新區塊。
- 溫室、光照、廚房鐮刀與水田、竹藤架、肉桂剝皮、砍樹後葉子掉落、大樹冠外圈會不會自己掉。
- 三個聯動包（樂牧、草本、酒館）。
- 三語切換、調過數值的食物、從舊版升級、效能。

## 其他觀察

- 測試世界從「Herbal 1.1 Test」複製設定，世界列表裡的名稱還是 Herbal 1.1 Test（資料夾是 `HarvestTest01=`）。
- `/place feature kaleidoscope_harvest:mandarin_tree_feature` 指令會說語法錯誤，因為柑橘沒有野生生成規則，指令的自動完成清單沒有它；腳本的 `placeFeature` 正常，樹苗也長得大，所以不影響遊戲。
- 內容記錄還有 10 筆「同一方塊的材質實例要用同一種 render_method」警告，記錄沒寫是哪些方塊，還沒查；畫面看起來正常，先記著。
